# 内容写作规范（CONTENT GUIDE）

本文件是 HyiBody 内容资产的写作与审核标准。目前覆盖两类内容：

- **信息卡文案**（`content/definitions/{zh,en}.json`）——点开一个结构时显示的"它是什么"
- **引导游览脚本**（`content/tours/*.json`）——一段可播放的三维讲解，"它正在做什么"

> **命名待定**：`tour` / 「故事线」这个叫法正在改。改名会同时动 i18n、文件名、URL 与
> UGC 界面，定下来之前本文件沿用旧称，代码里的 `Tour` 类型也不动。

规范的来源：2026-08-19 由四个专家 agent 对全部 189 条信息卡文案与三条脚本做了一轮
审核（解剖事实、英文准确性与中英一致性、中文文风、脚本结构），107 条发现里
77 条已套用。下面的硬规则大多能对应到一条自动化测试。

---

## 一、信息卡文案

### 字段与长度

| 字段 | 作用 | 中文上限 | 英文上限 |
|---|---|---|---|
| `blurb` | 信息卡正文，**一句话**说清"是什么、在哪、干什么" | 90 字符 | 190 字符 |
| `fact` | "你知道吗"，要有**可复述**的信息点 | 120 字符 | 240 字符 |

单行，不许换行。中英一一对应，`tests/unit/definitions.test.ts` 双向把关。

### 硬规则

1. **事实第一**。数字、位置、归属、机制都要能对上主流教科书。拿不准就换一个能确定的说法
2. **不传播已被推翻的说法**。已经踩过的坑：舌头味觉分区图、"眼球一生尺寸不变"、
   小肠表面积"一个网球场"（实测约 30 m²，2014 年 Helander & Fändriks）、
   肺表面积"半个网球场"（70 m² 对不上，网球场约 260 m²）
3. **不做医学建议**。可以说"医生常靠它判断"，不要说"建议你如何如何"。
   涉及急救与临床操作的说法要标明争议（如环状软骨加压已不再被指南推荐常规使用）
4. **一个知识点只在一处出现**。`fact` 不许是 `blurb` 的换句话说；相邻结构之间
   （肝门 vs 肾门、升结肠 vs 降结肠）不许用同一个句子模具
5. **比喻要准确，且不用被用滥的**。已下架：人体的第二心脏、信息高速公路、
   司令部/总指挥这类官职比喻、生造绰号（"背阔肌的小帮手""屈肘的老黄牛"）
6. **中文断句要念得通**。踩过的坑："锥体的尖叫肾乳头"、"下行为小腿供血"、
   "在肘部分出"——写完自己念一遍
7. **英文是英文，不是翻译腔**。全站统一英式拼写（defence / metres / oesophagus /
   caecum / disc / coeliac）。只在英语里成立的梗（funny bone）要说明它是英语俗名，
   不能写成"everyone calls it"

### 数字体例

同类概数统一用阿拉伯数字（"100 多万根"而不是"一百多万"）；字母形状不加引号
（`S 形`、`C 形`）；数字与单位之间留一个空格。

## 二、引导游览脚本

### 五拍骨架

每条器官脚本照这个骨架写，5–8 步 / 45–75 秒；系统级旗舰脚本 10–14 步 / 90–120 秒。

| 拍 | 做什么 | 典型参数 |
|---|---|---|
| **定场** | 全身宽景，抛出钩子，先不选中任何结构 | `preset: 'hero'`，`layer ≈ 0.05` |
| **认形** | 选中整个器官：它长什么样、在哪 | `selected`，`focus: true` |
| **拆内** | 打开或切开，看进去 | `expand` 或 `clip` |
| **连线** | 它的血管 / 神经 / 管道邻居，说明它怎么接进身体 | 换 `selected`，调 `layer` |
| **收尾** | 拉回宽景，一句带走，邀请自由探索 | `preset: 'hero'`，不设 `selected` |

**收尾这一拍不能省**：`TourEngine` 结束时只重置显隐、不动相机，没有收尾步的话
最后一帧就是"所有结构在一个特写周围突然弹回来"。

### 硬规则（都有对应的自动化测试）

1. **剖切面必须切到主角**。`clip.pos ∈ [-1, 1]` 映射的是**整具人体**的包围盒，
   不是结构自己的——手写这个数几乎必错。用 `clipPosForCoordinate` 从目标 bbox
   中心反算。心跳之旅第 4 步曾把 pos 写成 0.52，切面落在 y ≈ +76 mm 而心脏在
   y ∈ [-72, 27]，整颗心被切掉，11 秒白屏
2. **主角必须看得见**。选中结构所属系统在该 `layer` 下的不透明度要大于拾取阈值
   0.15。神经之旅第 2 步曾在 `layer 0.9` 选中垂体（属器官层，此时已淡到 0）
3. **相邻两步不许是同一帧**。至少在 `selected` / `expand` / `clip` / `preset` /
   `systems` 里改一项，或 `layer` 变化 ≥ 0.1
4. **文案不许和画面打架**。神经之旅第 4 步曾一边说"藏在椎骨管道里"，一边
   `systems: {skeleton: false}` 把椎骨关掉了
5. **展词里不许有生产备注**。"数据将在后续版本补充"这类话写进 `docs/STATUS.md`，
   不写给观众
6. **中英并行写、并行审**。英文必须承载与中文相同的具体意象，不能一边是画面
   一边只剩定义。测试按字符数比值（英文 / 中文 > 1.2）粗筛漏译
7. **数字只能有一个出处**。脚本里出现的数字，若 `definitions` 里同一 slug 也有，
   必须逐字一致

### 节奏

`durationMs` 用公式算而不是手填：

```
clamp(7000, round((4500 + 130 × 中文字数) / 500) × 500, 14000)
```

本步若改变了 `expand` / `clip` / `preset`，再 `+1500 ms` 留给相机飞行。

### 文案分工

信息卡负责"**它是什么**"，脚本负责"**它正在做什么、下一步去哪**"。
脚本不得复述 `definitions` 里的 `blurb` / `fact`——观众会先后看到两处，重复很刺眼。

### 每一步只能点名画面上有的东西

播放脚本时 `StructureLabel` 与 `InfoCard` 都被隐藏，展词是屏幕上唯一的标签。
所以每步文案必须点名当前 `selected` 的那个结构，也不许点名画面上没有的结构。

## 三、规模化之前要先做的事

要从 3 条扩到每个器官都有，下面几项得先落地，否则写完 100 个文件再改要改 100 次：

- [ ] **文件名 = 主结构 slug**（`kidney.json`、`liver.json`），`id` 与文件名一致；
      `src/tours/index.ts` 改成 `import.meta.glob` 自动收录。顺带支持 `?tour=kidney`
      深链，以及信息卡上的"看这段讲解"入口
- [ ] **Tour 类型补元数据**：`system`（菜单按系统分组，上百条时平铺列表不可用）、
      `estSec`（由 `durationMs` 求和生成，菜单上显示时长）、`level`（少儿 / 成人）
- [ ] **`structures` 字段**：每条脚本声明它讲到哪些结构，用来建反向索引——
      点开一个器官时列出"讲到它的几条内容"
- [ ] **`systems` 从 `boolean` 扩成 `boolean | number`**：把某系统压暗到 0.2 而不是
      关掉。"在 Y 里面看 X"是器官脚本每条都要用的动作，现在只能二选一
- [ ] **机位方向与距离解耦**：加一个 `from: 'front' | 'left' | …`，让 `preset` 只决定
      方向、`focus` 决定距离。现在两者互斥，小结构永远只能从上一步的角度看
- [ ] **`frameContent` 的相机改成 flyTo**：收起 `expand` 时相机现在硬切回 hero 再飞回来，
      每条用了 `expand` 的脚本都会撞上这一下弹跳
- [ ] **UGC 前置**：schema 版本号、id 稳定性约定、JSON Schema 校验文件

## 四、审核流程

新增或改动内容后，跑一轮专家审核：

1. **解剖事实**（中文）——只挑事实错误，不碰文风
2. **英文准确性与中英一致性**——含翻译腔与文化专属梗
3. **中文文风**——句式重复、比喻陈旧、`fact` 空洞、断句歧义
4. **脚本结构**——叙事弧、镜头语言、节奏、与信息卡的分工

审核产出统一格式（`slug` / `field` / `severity` / `current` / `suggested` / `reason`），
套用时**只在 `current` 与文件原文完全一致时才替换**，这样多份报告改到同一句时后者
自动跳过，由人裁决，不会互相覆盖。事实审核优先于文风审核。
